**Shprot** — это десктопное приложение, которое даёт вам надёжный, автоматически восстанавливающийся SOCKS5-прокси через SSH — без необходимости использовать командную строку.

В отличие от стандартных инструментов SSH-туннелирования, оно отслеживает состояние вашей сети, автоматически перезапускает оборванные соединения и даже адаптируется при смене Wi-Fi или выходе ПК из спящего режима. Встроенная генерация SSH-ключей и гибкие настройки прокси делают настройку простой и безопасной.

Будь вы разработчиком, тестировщиком или просто пользователем, которому нужен стабильный прокси для повседневного сёрфинга, Shprot поддерживает ваше соединение в рабочем состоянии с минимальными усилиями.

## ✨ Возможности

- **Автоматическое туннелирование SSH:** Простая настройка и управление защищенными SSH-туннелями, которые перенаправляют трафик через локальный SOCKS5-прокси.
- **Умная отказоустойчивость соединения:** Автоматический мониторинг статуса интернета и сетевых переключений (например, смена сетей Wi-Fi или выход ПК из спящего режима) с прозрачным перезапуском туннеля.
- **Продвинутые проверки работоспособности:** Периодическая проверка целостности соединения путем тестирования доступности популярных веб-сайтов через прокси; мгновенное восстановление туннеля в случае зависания фонового SSH-процесса.
- **Встроенное управление ключами:** Упрощенная аутентификация клиента с помощью встроенной генерации криптографических пар ключей, что позволяет легко скопировать открытый ключ в файл `authorized_keys` на удаленном сервере.
- **Удобная авторизация:** Понятный интерфейс для управления учетными данными удаленного сервера и параметрами аутентификации сервера/клиента.
- **Гибкие сетевые настройки:** Полный контроль над локальным адресом привязки и портами для вашего SOCKS5-прокси сервера.
- **Поддержка опционального HTTP-прокси:** В дополнение к SOCKS5-прокси вы можете включить отдельный HTTP-прокси, который перенаправляет трафик через тот же SSH-туннель. Это полезно для устаревших приложений или скриптов, которые поддерживают только HTTP-прокси.
  
## 💻 Системные требования

Shprot доступен для платформ **Windows** и **Linux**:

- **Windows:** Windows 10 / 11 (64-bit)
- **Linux (DEB-пакеты):** Ubuntu 22.04 или новее, Debian 12 или новее, и другие совместимые дистрибутивы
- **Linux (RPM-пакеты):** Fedora 39 или новее, RHEL 9 / AlmaLinux 9 или новее

## 🚀 Установка

Shprot доступен для платформ Windows и Linux. Выберите подходящий пакет для вашей операционной системы в разделе **[Релизы](../../releases)**.

### Windows
Скачайте готовый NSIS-инсталлятор для Windows (файл `.exe`). Просто запустите загруженный файл и следуйте инструкциям мастера установки.

### Linux (DEB-дистрибутивы)
Для Ubuntu, Debian и других DEB-систем скачайте `.deb`-пакет и установите его с помощью:

    sudo dpkg -i shprot_*.deb
    sudo apt-get install -f  # Разрешение зависимостей

Пакет собран на Ubuntu 22.04 и должен работать на всех более новых версиях Ubuntu, Debian 12+ и совместимых дистрибутивах.

### Linux (RPM-дистрибутивы)
Для Fedora, RHEL, AlmaLinux и других RPM-систем скачайте `.rpm`-пакет и установите его с помощью:

    sudo rpm -i shprot-*.rpm

Или на Fedora/RHEL с DNF:

    sudo dnf install ./shprot-*.rpm

Пакет собран на Fedora 39 и должен работать на Fedora 39+, RHEL 9+, AlmaLinux 9+ и совместимых дистрибутивах.

## 🖥️ Настройка сервера (Повышение безопасности)

Для обеспечения максимальной безопасности настоятельно рекомендуется создать на удаленном Linux-сервере (например, Ubuntu/Debian) отдельного пользователя с ограниченными правами специально для SSH-туннелирования. Это предотвратит доступ к командной оболочке или выполнение произвольных скриптов на вашем сервере через этот аккаунт.

Выполните следующие шаги для настройки сервера:

### 1. Создание пользователя с ограниченными правами
Выполните команду для создания системного пользователя по имени `tunnel` без права входа в шелл и с заблокированным домашним каталогом:

    sudo useradd -r -s /bin/false -m tunnel

### 2. Настройка SSH-демона
Откройте конфигурационный файл SSH с правами суперпользователя:

    sudo nano /etc/ssh/sshd_config

Прокрутите файл в самый низ и добавьте следующий блок `Match User`. Это изолирует пользователя `tunnel`, отключит выделение интерактивного терминала и разрешит только перенаправление TCP-трафика:

    Match User tunnel
        AllowTcpForwarding yes
        X11Forwarding no
        PermitTTY no
        ForceCommand echo "This account is for SSH tunneling only."

*Сохраните файл и перезапустите службу SSH для применения изменений: `sudo systemctl restart ssh`.*

### 3. Добавление открытого ключа Shprot
Теперь добавьте открытый ключ, сгенерированный в Shprot, в окружение нового пользователя. Переключитесь на root или используйте `sudo`, чтобы настроить файл `authorized_keys`:

    # Создаем директорию .ssh с правильными правами доступа
    sudo mkdir -p /home/tunnel/.ssh
    sudo chmod 700 /home/tunnel/.ssh

    # Добавляем ваш открытый ключ Shprot
    echo "ваш-открытый-ключ-из-Shprot" | sudo tee -a /home/tunnel/.ssh/authorized_keys

    # Корректируем владельца и права доступа к файлу
    sudo chmod 600 /home/tunnel/.ssh/authorized_keys
    sudo chown -R tunnel:tunnel /home/tunnel/

После завершения настройки используйте `tunnel` в качестве **SSH-имени пользователя** при конфигурации подключения в десктопном приложении Shprot.

## 🔧 Настройка приложения

Shprot работает полностью независимо от глобальных конфигураций SSH вашей системы или ранее созданных ключей пользователя, опираясь исключительно на собственные внутренние настройки для лучшей изоляции и безопасности.

<img src="Assets/Screenshot.png" alt="Интерфейс Shprot" width="571" height="547">

Выполните следующие шаги для настройки прокси-туннеля:

### Шаг 1: Включение туннеля
1. Установите флажок в чекбоксе **"Enable SSH Proxy Tunnel"**. 
   * *Примечание: Все остальные элементы управления формой останутся заблокированы, пока этот флаг не установлен. Вы можете снять его в любое время, чтобы временно отключить туннель без потери введенных настроек.*

### Шаг 2: Настройка удаленного сервера
1. В поле **"SSH Destination"** введите данные подключения в стандартном формате: `username@host[:port]` (например, `tunnel@192.0.2.1:22`).
2. *(Опционально)* Нажмите кнопку **"Run Trust Check"** над полем. Это проверит, доверяет ли уже Shprot ключу этого хоста. Вы можете использовать эту кнопку позже для ручной диагностики, если сервер был переустановлен или если вы подозреваете сетевую аномалию.

### Шаг 3: Настройка аутентификации клиента по ключу
1. Перейдите к области **"SSH Private Key"**. Чтобы указать защищенный ключ клиента, вы можете:
   * Вставить существующий текст приватного ключа в текстовое поле.
   * Нажать **"Import…"** для загрузки ключа из файла.
   * Нажать **"Generate"** (Рекомендуется), чтобы Shprot мгновенно создал новую пару криптографических ключей.
2. Нажмите **"Copy Public Key"**, чтобы скопировать текст сгенерированного открытого ключа в буфер обмена.
3. Откройте терминал сервера и добавьте этот ключ в файл ограниченного пользователя, как показано в разделе «Настройка сервера».

### Шаг 4: Настройка локального SOCKS5-прокси
1. Проверьте параметры маршрутизации прокси:
   * **Local SOCKS5 Proxy Address:** По умолчанию используется `localhost` (доступ к прокси открыт только для текущего компьютера). Измените на `0.0.0.0`, если хотите расшарить прокси для других устройств в вашей локальной сети.
   * **Port:** По умолчанию используется `1080`. Вы можете изменить его, если порт `1080` уже занят другой службой в вашей системе.

### Шаг 5: Настройка локального HTTP-прокси (опционально)
Если вам нужен HTTP-прокси в дополнение к SOCKS5, установите флажок **"Enable Local HTTP Proxy"**. Это разблокирует два поля:

- **Local HTTP Proxy Address:** По умолчанию установлено `localhost` (как и для SOCKS5). Измените на `0.0.0.0`, чтобы расшарить HTTP-прокси для других устройств в вашей локальной сети.
- **Port:** По умолчанию используется `8080`. Вы можете изменить его, если этот порт уже занят.

HTTP-прокси работает **через** тот же SSH-туннель, что и SOCKS5-прокси, поэтому не требует дополнительной настройки на сервере. После включения оба прокси будут доступны одновременно.

### Шаг 6: Сохранение и запуск соединения
1. Нажмите кнопку **"Save"**. Shprot автоматически выполнит валидацию всех полей. Если будут обнаружены ошибки, приложение подсветит некорректные поля и подскажет, что нужно исправить.
2. **Проверка хоста (Первое подключение):**
   Если вы подключаетесь к этому серверу впервые, появится диалоговое окно с отображением **фингерпринта открытого ключа сервера**.
   * *💡 Технический совет (Как проверить): Чтобы предотвратить атаки типа Man-in-the-Middle, вы можете проверить этот фингерпринт, выполнив команду `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` (или указав путь к конкретному файлу ключа хоста) прямо в консоли вашего сервера и сверив полученный хэш.*
3. Подтвердите доверие в диалоговом окне. Shprot сохранит параметры и сразу запустит фоновый движок для открытия и поддержки туннеля.

### 📊 Индикаторы статуса соединения
Вы можете легко отслеживать статус туннеля, не открывая главное окно:
* **Иконка в системном трее:** Яркая **цветная иконка** означает, что туннель активен и SOCKS5-прокси успешно пропускает трафик. Иконка в **оттенках серого** указывает на то, что туннель закрыт или отключен.
* **Всплывающие уведомления:** Приложение будет отправлять нативные системные уведомления каждый раз, когда туннель успешно подключается или падает.

## 🛠 Сборка и разработка

### 1. Подготовка окружения

Перед сборкой или открытием проекта убедитесь, что конфигурация вашего окружения соответствует следующим требованиям:

- **ОС:** Windows 10/11 (64-bit) или Linux (Ubuntu 22.04+, Fedora 39+)
- **Компилятор:** 
  - Windows: MSVC 2022 (x64)
  - Linux: GCC 11 или новее (или Clang 14+)
- **Фреймворк:** Qt 6.11.2
- **Система сборки:** CMake (версия 3.20 или выше)
- **Генератор сборки:** Ninja (настоятельно рекомендуется для ускорения компиляции) или MSBuild
- **Генераторы пакетов:** 
  - Windows: NSIS
  - Linux: Кастомные скрипты с использованием `fakeroot`/`dpkg-deb` (для DEB) и `rpmbuild` (для RPM)

Выполните следующие шаги, чтобы клонировать репозиторий:

    git clone https://github.com/andrew-markin/shprot.git
    cd shprot

### 📦 Вариант А: Сборка релизного пакета

Проект использует переменные окружения для настройки через файл `.env`. Скопируйте пример файла окружения:

    cmake -E copy .env.example .env

Откройте созданный файл `.env` и установите переменную `QT_PREFIX`, указав путь к вашей локальной установке Qt 6.11.2:

- **Windows (MSVC):**

      QT_PREFIX=C:\Users\YourUsername\Qt\6.11.2\msvc2022_64

- **Linux (только для нативной сборки):**

      QT_PREFIX=/home/yourusername/Qt/6.11.2/gcc_64

> **Примечание:** Файл `.env` требуется в основном для сборки под Windows. Для Linux рекомендуется использовать Docker-сборку (см. ниже), которая не требует локальной установки Qt.

#### Сборка под Windows
Запустите автоматический релизный скрипт из корневого каталога проекта:

    ReleaseWindows.cmd

После завершения работы скрипта готовый NSIS-инсталлятор (`.exe`) появится в папке **`Release`**.

#### Сборка под Linux (Рекомендуется: через Docker)

Сборка Linux-пакетов выполняется с использованием Docker для обеспечения согласованности и воспроизводимости. Этот подход создает чистые, изолированные среды сборки со всеми необходимыми зависимостями.

**Требования:** Установите [Docker](https://docs.docker.com/engine/install/) на вашей машине разработки.

**Доступные скрипты сборки:**

1. **Для DEB-дистрибутивов (Ubuntu 22.04+):**

       ./ReleaseUbuntu.sh

Создает `.deb`-пакет с использованием `dpkg-deb`, совместимый с Ubuntu 22.04 и новее, Debian 12 и новее.

2. **Для RPM-дистрибутивов (Fedora 39+):**

       ./ReleaseFedora.sh

Создает `.rpm`-пакет с использованием `rpmbuild`, совместимый с Fedora 39 и новее, RHEL 9 / AlmaLinux 9 и новее.

**Важные замечания о Docker-сборке:**

- **Первая сборка занимает время:** Первый запуск любого из скриптов может занять **более часа**, так как он собирает Docker-образы и компилирует облегченную, кастомизированную версию Qt 6.11.2 из исходников. Это однократная настройка.
- **Последующие сборки выполняются быстро:** После того как Docker-образы сохранены в кэше локально, все следующие сборки будут значительно быстрее (обычно несколько минут).
- **Локальный Qt не требуется:** Поскольку Qt встроен в Docker-контейнеры, вам не нужно настраивать `.env` или устанавливать Qt на вашей хост-системе.
- **Расположение выходных файлов:** Все созданные пакеты (`.deb` или `.rpm`) появятся в папке **`Release`**, так же как и установщик для Windows.

#### Сборка под Linux (Альтернатива: Нативная)

Если вы предпочитаете собирать нативно без Docker, вы можете сделать это, установив необходимые зависимости для сборки и настроив `.env` с путем к вашей локальной Qt.

**Необходимые пакеты:**

- **Ubuntu/Debian:**

      sudo apt-get install build-essential cmake fakeroot dpkg-dev file ninja-build patchelf

- **Fedora/RHEL:**

      sudo dnf install cmake file gcc-c++ make ninja-build patchelf rpm-build

После установки зависимостей и настройки `QT_PREFIX` в `.env` вы можете собрать проект напрямую с помощью CMake. Однако **настоятельно рекомендуется использовать Docker-сборку**, так как она создает более согласованные и переносимые пакеты.

### 💻 Вариант Б: Работа с кодом (Разработка)

Если вы хотите изменить код, исправить баги или добавить новые фичи, вам следует использовать **Qt Creator**:

1. Откройте **Qt Creator**.
2. Выберите **Open Project** и перейдите в каталог **`Sources`**.
3. Откройте файл **`CMakeLists.txt`**, расположенный внутри папки `Sources`.
4. При появлении запроса на настройку проекта выберите ваш локальный комплект **Qt 6.11.2**, настроенный в вашей IDE.
   - *Совет: Для значительно более быстрой сборки мы настоятельно рекомендуем использовать **Ninja** в качестве генератора CMake в настройках вашего комплекта вместо стандартного генератора.*
5. Установите каталог сборки так, чтобы он указывал на папку **`Builds`** в корне проекта (например, `../Builds/build-Shprot-Desktop-Debug`).

Для разработки под Linux вы можете использовать тот же подход с Docker или установить Qt 6.11.2 нативно на вашу систему.

Теперь вы можете писать код, отлаживать и запускать приложение прямо из IDE. Промежуточные файлы сборки будут изолированы внутри папки `Builds`.

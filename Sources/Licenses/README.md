# Licenses

License texts shown in the About dialog. They are embedded into the executable via `Resources.qrc`.

| File | Contents | Tab in the About dialog |
|------|----------|-------------------------|
| `../../LICENSE` | GNU GPL v3, the license of Shprot itself | License |
| `LGPL-3.txt` | GNU LGPL v3, the license Qt is used under | Qt |
| `ThirdParty.txt` | Notices of third-party components that Qt is built with | Third-Party Notices |

## Updating third-party notices

`ThirdParty.txt` is generated by `GenerateThirdParty.py` and must be regenerated whenever Qt is updated
(versions, copyrights and the set of bundled components change between Qt releases).

1. Install documentation for the new Qt version with Qt Online Installer (or Maintenance Tool).
   Attribution pages are installed to `~/Qt/Docs/Qt-X.Y.Z/<module>/<module>-attribution-*.html`.

2. Run the script with the documentation directory:

   ```bash
   python3 Sources/Licenses/GenerateThirdParty.py ~/Qt/Docs/Qt-X.Y.Z
   ```

3. Review the diff of `ThirdParty.txt`. If a new component appears, check whether it really gets into
   deployed binaries; if it does not (a build system part, another platform, a disabled feature or a plugin
   that is not deployed), add it to `EXCLUDED` in the script and run it again. The script warns about
   excluded components that are not present anymore, so they can be removed from the list.

The script must also be updated when:

- the application starts using another Qt module (add it to `MODULES`);
- Qt configuration in `Dockerfile.*` or the list of deployed plugins in `CMake/Deploy*.cmake` changes,
  e.g. JPEG image plugin is deployed (remove `libjpeg` from `EXCLUDED`).

Components used on one platform only (e.g. D3D12 and Wintab on Windows, XCB on Linux) are kept,
since the same notices file is used for all platforms.
